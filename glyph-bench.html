MarkRight · glyph metrology

Measure the glyphs where they actually render.

This measures advance width, adjacency shift and width class in this browser, on this device, in the font you name — not in whatever fonts a build container happens to ship. Open it on Fedora and on Android and compare.

It cannot tell you a font's name — no browser exposes that to script. Naming instructions are at the foot of the page.

Specimen

Width groups

Glyphs sharing an advance are grouped. A single group means the set is uniform and will column-align. Green edge is a lone group; red edge means that group is one of several.

Per glyph

glyphcodepointclassalonein runshiftflag

Shift is the advance beside the anchor minus the advance alone. Non-zero means the glyph is being drawn from a different font once it has a neighbour — the run got re-itemised. Kerning can also produce a small shift, so treat single-digit values as inconclusive and large ones as font substitution.

Naming the font

Chrome, either platform

DevTools → Elements → select the text node → Computed pane → scroll to Rendered Fonts. It lists every font that supplied glyphs in that node, with a glyph count each. Two entries for one set of markers is the substitution you're chasing.

For Chrome on Android: connect by USB, open chrome://inspect in desktop Chrome, and you get the same DevTools against the phone. It's the only reliable per-glyph readout on Android.

Firefox

Inspector → Fonts panel. Shows "Fonts used" for the current selection, which is a cleaner readout than Chrome's.

Fedora, command line

fc-list ':charset=25CB' family file    # every font holding U+25CB
fc-match ':charset=25CB'               # what fontconfig picks
fc-match -s ':charset=25CB' | head     # the sorted fallback chain

Hex codepoint, no U+. Note fontconfig's answer is what it would pick — an application with its own fallback logic may differ, so treat it as a shortlist rather than a verdict.

Android, system side

adb shell ls /system/fonts
adb shell cat /system/etc/fonts.xml

fonts.xml is the fallback order itself, and will tell you where the symbol faces sit in the chain relative to the CJK and emoji faces.

For the U+29Bx circled run specifically, this is settled: the supplier is NotoSansSymbols-Regular-Subsetted.ttf, Android's reduced build of Noto Sans Symbols — not Symbols 2, and not Noto Sans Math. Both of those were inferred and then retracted. The advance discriminates them: Noto Sans Math gives 836, the device gives 796.
